# CLAUDE.md – guide for AI assistants

Let's Gau is an AI-curated, static event calendar. The full spec is
`docs/CONCEPT.md` (German, the source of truth); everything technical in the
repo is English.

## File map

| Path | What |
| --- | --- |
| `docs/CONCEPT.md` | full specification and phase plan (do not edit without being asked) |
| `docs/ISSUES.md` | milestones, labels and issues per phase |
| `docs/ARCHITECTURE.md` | Mermaid diagrams: context, container, sequence, status |
| `docs/DATA_MODEL.md`, `docs/CONFIGURATION.md`, `docs/OPERATIONS.md` | reference docs |
| `docs/decisions/` | ADRs (`ADR-001-...md`) |
| `instance/config.yaml` | the Schongau instance config, validated by `src/letsgau/config.py` |
| `instance/sources/` | `whitelist.yaml`, `blacklist.yaml`, `suggested.md` |
| `instance/content/` | Markdown content pages (`*.de.md`, `*.en.md`) |
| `examples/instance/` | templates with `{{PLACEHOLDER}}`s for `letsgau init` |
| `src/letsgau/` | `cli`, `init`, `scheduler`, `config`, `models`, `geo`, `discovery`, `crawl`, `merge`, `ai_runner`, `build` |
| `prompts/` | `discovery.md`, `events.md`, `merge.md` |
| `templates/`, `static/`, `i18n/` | Jinja2 templates, CSS/JS, UI strings (`de.yaml`, `en.yaml`) |
| `tests/` | pytest; AI responses are recorded fixtures, tests never call an AI |
| `.github/workflows/` | `ci.yml` (lint + tests), `geo-check.yml` / `crawl-check.yml` (live checks), `run.yml` (pipeline, Phase 6) |

Generated: `site/` (gitignored), `data/` and `geo/` (bot-only `data` branch).

## Commands

```bash
pip install -e '.[dev]'
python -m letsgau --help
python -m letsgau check                     # validate instance/config.yaml
python -m letsgau run --job geo --dry-run   # places + drive times (needs ORS_API_KEY)
python -m letsgau run --job events --dry-run --limit-places 3
ruff check . && ruff format --check . && pytest
```

## Conventions

- Language: code, comments, docstrings, commits, PRs, issues, prompts, config
  keys/comments, tag IDs, file names, logs and repo docs are **English**.
  German only in website content: `i18n/de.yaml`, `instance/content/*.de.md`.
- Python 3.12, Pydantic v2, Jinja2, Ruff (line length 100), pytest.
- Every module starts with a docstring; every `config.yaml` option is commented
  and documented in `docs/CONFIGURATION.md`.
- Config models reject unknown keys (`extra="forbid"`); errors include file,
  line and field.
- Commits follow Conventional Commits; every PR adds a line to `CHANGELOG.md`
  under `Unreleased`; one PR per phase, `Closes #N` for its issues.
- Instance-specific (Schongau) things go into `instance/`, never into code.

## Never

- Never commit secrets (`.env`, tokens, API keys).
- Never edit `site/` by hand; it is generated by `letsgau run --job build`.
- Never change the data schema without a migration of the JSON files in `data/`.
- Never change a prompt in `prompts/` without a test run using `--dry-run`.
- Never call the Claude API directly with `CLAUDE_CODE_OAUTH_TOKEN`; in
  subscription mode only the `claude` CLI may use it.
- Never commit generated data to `main`; the bot writes to the `data` branch.
